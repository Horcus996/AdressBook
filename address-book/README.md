## 1. Overview

This is a web-based address book application. It supports contact CRUD, bookmarking, multiple contact methods per contact, and Excel (`.xlsx`) import and export. The project uses a lightweight architecture with no database to install; after downloading the source code, follow the steps below to start and demo it locally.

## 3. Technology Stack and Rationale

| Layer | Technology | Rationale |
|---|---|---|
| Backend | Python 3 + Flask | Lightweight web framework with clear routes and fast startup; easy for pair collaboration and later cloud deployment |
| Excel processing | openpyxl | Standard Python library for reading and writing `.xlsx`, supporting headers, column widths and cell content |
| Frontend | Plain HTML / CSS / JavaScript | No build step required; reviewers can run the page directly with minimal environment dependencies |
| Persistence | Local JSON file (`data/contacts.json`) | Sufficient for course-demo scale; no database to install; sample data is generated on first launch |

**Why no database:** the assignment does not require multi-user access, concurrency or persistence scale, so a JSON file already covers CRUD and import/export. If the system later grows into a multi-user product, it can be migrated to SQLite or another database smoothly.

## 5. Data Model

The contact fields are consistent across frontend and backend:

| Field | Type | Required | Description |
|---|---|:---:|---|
| `id` | integer | Auto | Unique id, generated by the backend |
| `name` | string | Yes | Contact name |
| `bookmarked` | boolean | No | Whether the contact is bookmarked, default `false` |
| `phones` | string[] | No | Phone number list, multiple allowed |
| `emails` | string[] | No | Email address list, multiple allowed |
| `socials` | string[] | No | Social accounts (WeChat / QQ / GitHub / Instagram, etc.) |
| `address` | string | No | Postal address |
| `note` | string | No | Note (relationship, company, etc.) |

Design notes: multi-value fields are stored as arrays and joined into strings only when displaying or exporting; empty values are stored as empty strings or empty arrays, never mixed with `null`.

## 6. Feature Details

### 6.1 Bookmark Contacts

**Goal:** users can mark frequent or important contacts as favorites, and those contacts are easy to recognize and reach quickly.

Implementation:

1. The data model adds a `bookmarked` boolean field to each contact, persisted to JSON so the state survives restarts.
2. The backend exposes `POST /api/contacts/<id>/bookmark`, which toggles the state between `true` and `false`.
3. The list endpoint supports the `?favorite=1` query parameter to return only bookmarked contacts, used by the Favorites filter page.
4. On the card, a star button shows the state: a gold filled star `★` when bookmarked, a gray hollow star `☆` otherwise; clicking it calls the toggle endpoint and refreshes the list.
5. The header statistics show the total contact count and the favorite count in real time.

### 6.2 Multiple Contact Methods

**Goal:** one contact can hold several pieces of contact information: phone numbers, emails, social accounts and a postal address.

Implementation:

1. `phones`, `emails` and `socials` are string arrays, which naturally support multiple records per field; `address` is a single text value.
2. In the add/edit modal, each of the three method groups is a set of dynamic input rows: click "+ Add …" to add a row, click the `✕` at the end of a row to remove it; on save, all non-empty entries are collected.
3. The backend cleans values before saving: trim surrounding spaces and filter out empty entries; imported data goes through the same cleaning.
4. On the card, information is grouped under Phone / Email / Social, each entry shown as a chip; the address is displayed on its own line.

### 6.3 Excel Import and Export

**Export format (`.xlsx`):**

| Column | Content | Example |
|---|---|---|
| Name | Contact name | Alice Wang |
| Bookmarked | `Yes` / `No` | Yes |
| Phones | Multiple phones, semicolon-separated | 138-0000-0001; 0591-88880001 |
| Emails | Multiple emails, semicolon-separated | alice.wang@example.com |
| Social Accounts | Multiple social accounts, semicolon-separated | WeChat: alice_wx; QQ: 100001 |
| Address | Postal address | No. 1 Gongye Road, Fuzhou |
| Note | Note | Lab partner |

Rules: the first row is a labeled header; each contact occupies one row; column widths are adjusted for readability.

**Export flow:** the backend creates a workbook with openpyxl → writes the header → appends one row per contact → writes to an in-memory buffer → downloads it in the browser as `contacts.xlsx`.

**Import flow:**

1. The browser uploads the `.xlsx` file; the backend reads the active worksheet with openpyxl.
2. The first header row is mapped to canonical fields through an alias table that recognizes common English column names (for example, `Phone` → `phones`).
3. Rows are parsed one by one: rows without a name are skipped and counted as `skipped`; multi-value cells are split into arrays on semicolons or commas; bookmark marks such as `Yes/No/True/1` are parsed as booleans.
4. Successfully parsed contacts are appended to the address book, saved to local JSON, and the import and skip counts are returned.
5. A `Download Template` button provides a blank template with a header and one example row, so the import format stays consistent.

**Fault tolerance:** a clear error message is returned when the file cannot be parsed; blank rows are ignored automatically; a corrupted local data file falls back to sample data instead of crashing the application.

### 6.4 Additional UX Features

- **Search:** real-time fuzzy matching across name, phone, email, social account, address and note.
- **Filter:** switch between All and Favorites tabs.
- **CRUD:** create and edit through the modal form; delete asks for confirmation first.
- **Feedback:** success and failure messages appear through a bottom toast.

## 7. Running Locally

### 7.1 Requirements

- Python 3.10 or higher (development environment: Python 3.13)
- Network access to the Python package index to download dependencies

### 7.2 Install and Start (Windows)

Open PowerShell in the project root `address-book/`:

```powershell
# 1. Install dependencies
python -m pip install -r requirements.txt

# 2. Start the application
python app.py

# 3. Open in the browser
#    http://127.0.0.1:5000
```

### 7.3 macOS / Linux

```bash
python3 -m pip install -r requirements.txt
python3 app.py
# Open http://127.0.0.1:5000 in the browser
```

### 7.4 Run the Smoke Test

No running server is needed; the check uses the Flask test client:

```powershell
python tests/smoke_test.py
```

The test covers: health check, sample data loading, create, favorite filter, bookmark toggle, update, export header and row count, import parsing, imported field validation, export round-trip validity, and delete. When everything passes, the final line is `All smoke tests passed.`.

## 8. Excel File Format

- Supported format: `.xlsx` (the legacy `.xls` is not supported).
- The first row of the import file must be a header; column order may differ, as columns are recognized by name.
- Recognized header aliases are in `HEADER_ALIASES` in `app.py`; the name column is required, and other columns default to blank when missing.
- Multiple records inside one cell are separated by `;` or `,`.
- Prefer filling in the template downloaded from the `Download Template` button to avoid format incompatibility.

## 11. Known Limitations and Possible Extensions

1. **Single-user local use:** there is no login or multi-user isolation; data is stored in a local JSON file.
2. **Append-only import:** importing does not overwrite existing contacts; an import mode option ("clear before import") can be added to the backend later.
3. **No database:** data can be migrated to SQLite as the volume grows; file persistence is sufficient at the current scale.
4. **Cloud deployment is optional:** a local `localhost` link does not count toward the deployment bonus; public deployment steps are in the guide.

## 12. Troubleshooting

| Symptom | Direction |
|---|---|
| `python` is not recognized | Install Python and enable "Add Python to PATH", or use the `py` launcher |
| Dependency installation fails | Check the network; use a mirror index if needed, or upgrade pip: `python -m pip install --upgrade pip` |
| Port 5000 is occupied | Change the port in `app.run(port=...)` at the end of `app.py`, or close the occupying process |
| Import says the file cannot be read | Confirm the upload is `.xlsx` (not `.xls`), the file is not corrupted and not locked by another program |
| Garbled characters | Make sure files are saved as UTF-8; the browser page already declares UTF-8 encoding |
| Data lost after restart | Check whether `data/contacts.json` was deleted or wrongly excluded by `.gitignore`; local data is not synced with the repository by design |
